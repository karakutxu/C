Full run sequence
1. Setup
sudo ./setup_vm_test.sh
2. Compile
gcc proto_demo.c -o proto_demo
3. Receiver
Terminal 1
sudo ip netns exec nsB bash

then:

./proto_demo rx tun0 dummy
4. Sender
Terminal 2
sudo ip netns exec nsA bash

then:

./proto_demo tx tun0 192.168.100.2

IMPORTANT:

192.168.100.2 is the UNDERLAY destination
5. Generate overlay traffic
Terminal 3
sudo ip netns exec nsA bash

then:

ping 10.20.0.1
Expected output
Sender
TX: 10.10.0.1 -> 10.20.0.1 len=84
Receiver
RX: 10.10.0.1 -> 10.20.0.1 len=84
Why this is now the correct architecture

This now closely matches your discovered legacy design:

Legacy	Linux Port
routing sockets	Netlink
AF_INET sockets	UDP sockets
logical overlay	TUN overlay
custom forwarding	userspace daemon
kernel routing table	Linux FIB

and avoids unnecessary:

AF_PACKET
Ethernet framing
MAC handling
Layer-2 complexity

which your legacy code likely never relied upon.
